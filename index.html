claude code / commands

Slash Command Notebook

Claude Code(ターミナルで動く Anthropic のコーディングエージェント CLI)では、対話シェルに / で始まる「スラッシュコマンド」を打って機能を呼び出す。本ページはそれらを実際に実行し、「ユーザーの入力」と「Claude の最終出力・画面」のペアを Notebook 形式で記録したもの。対象は、公式ドキュメント code.claude.com/docs/en/commands に掲載の全 80 超のコマンドからよく使う組み込み 34 個と、カスタムコマンドの実例 1 個(/explain)。

コマンドは 2 種類に大別される: プロンプト注入型(コマンドの実体として登録された指示プロンプト — Claude Code でいう Skill — がモデルに渡り、出力が返る)と UI/ハーネス型(CLI 本体=ハーネスが画面上で処理し、モデルは関与しない)。/compact や /recap のように、モデル呼び出しがセッションの外側で行われる中間形も少数ある。前者は §1 で入力と出力を、後者は §2 で端末画面を実測した(中間形は §1 に含めた)。

姉妹ページ: Config Notebook — 同じ依頼文のまま設定(outputStyle・deny・defaultMode・sandbox)を切り替えると出力がどう変わるかの実測比較。

§1実行デモ — プロンプトと出力の実測

デモ用サンプルプロジェクト(Python 製の小さな電卓で、意図的にバグと脆弱性を仕込んである)に対して claude -p "/コマンド" によるヘッドレス実行(対話 UI なしで 1 回だけ実行するモード)で最終出力を Out に採取した。例外として /btw と /compact は対話モードでの実測(各セルの注記を参照)。セルは Setup と /init を先頭に置き、以降はアルファベット順。カスタムコマンドの /explain だけは組み込みコマンドと区別するため末尾に置いた。多くのセル末尾に付けた「端末画面(実測)」は対話モードでの別回の実行のため、Out と内容が一致しないことがある。

Both findings scored 8/10 confidence — above the ≥8 threshold — so both are retained.

# Vuln 1: Command Injection: src/user_db.py:18

  • Severity: High / Category: command_injection
  • Description: ping_host() concatenates the host argument directly into a string passed to os.system(), which executes via the shell. Any shell metacharacters in host allow arbitrary command execution.
  • Exploit Scenario: A caller invoking ping_host("8.8.8.8; rm -rf /") causes arbitrary commands to run with the process's privileges.
  • Recommendation: Use subprocess.run(["ping", "-c", "1", host], shell=False) and validate that host matches a legitimate hostname/IP format before use.

# Vuln 2: Authentication Bypass: src/user_db.py:15

  • Severity: High / Category: authentication_bypass
  • Description: login(name, password) never checks name — it only compares password against a single hardcoded constant. Anyone who knows this one value is authenticated as any username, including admin.
  • Exploit Scenario: An attacker calls login("admin", "hunter2") and is authenticated as the admin account regardless of the actual credential-to-user mapping.
  • Recommendation: Store per-user hashed credentials (e.g., bcrypt/argon2) and validate against the specific name's stored hash. Use a constant-time comparison (hmac.compare_digest) instead of ==.

以下のコマンドは CLI 自身が処理し、コマンド自体のプロンプトはモデルに送られない(ただし /goal のように、設定をきっかけに通常ターンの自律動作が始まるものはある)。「出力」は端末画面なので、対話モードで実行した直後の画面をカラー付きで採取した(採取条件の詳細は末尾の「取得方法」)。表示内容(モデル一覧・使用量・セッション一覧など)は環境依存であり、この環境での一例。メールアドレスなどは伏せ字にしてある。セルはアルファベット順。

[1] login() has multiple critical security defects  (severity: normal, src/user_db.py:13-15)
    The newly added `login()` in src/user_db.py:13-15 has three compounding security defects: (1)
    the `name` argument is never used, so anyone supplying the single hardcoded password
    authenticates as any user — a complete authentication bypass; (2) `ADMIN_PASSWORD = "hunter2"`
    is a plaintext credential in source, permanent in git history, unrotatable without a code
    change, and a well-known wordlist password; (3) the `==` comparison is not constant-time and
    leaks the secret byte-by-byte via timing. Fix: look up a per-user credential (bcrypt/argon2
    hash) from storage keyed by `name`, and verify with `hmac.compare_digest` or the hashing
    library's constant-time verify.

[2] Command injection in ping_host via unsanitized host  (severity: normal, src/user_db.py:17-19)
    Command injection RCE: `ping_host(host)` at src/user_db.py:19 passes `"ping -c 1 " + host` to
    `os.system`, so any shell metacharacter in `host` (e.g. `ping_host("example.com; rm -rf ~")`)
    executes arbitrary commands. Fix by using `subprocess.run(["ping", "-c", "1", host])` without
    `shell=True` (and/or validate `host` as a hostname/IP).

[3] [quality] Function-level import of os inside ping_host  (severity: nit, src/user_db.py:17-19)
    The new `ping_host` function imports `os` inside the function body while the rest of the module
    imports (`sqlite3`, `subprocess`) live at the top — a minor inconsistency. Since `subprocess` is
    already imported at module level, the cleanest fix is to drop the `os` import entirely and use
    `subprocess.run` here too.
